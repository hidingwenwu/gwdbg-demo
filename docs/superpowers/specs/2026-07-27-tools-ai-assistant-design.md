# 工具线 AI 智能客服助理设计

> 日期：2026-07-27 ｜ 状态：待评审 ｜ 范围：`gwdbg-demo` 原型工具线页面

## 1. 目标与范围

在工具页及全部工具子页内增加"AI 智能客服助理"，以悬浮球形态常驻展示；点击后打开演示版 AI 聊天界面，交互 1:1 参考 E50 的"技术&服务"（`device-e50-service.html` 技术支持聊天页）。

涉及页面（均属于 `_base.css` + `interactions.js` 的工具线模板）：

- `pages/tab-tools.html`（工具 Tab 首页）
- `pages/tool-fluoro-input.html` / `tool-fluoro-result.html` / `tool-fluoro-submit.html`（氟机支持查询流程）
- `pages/tool-wiring.html` / `tool-videos.html` / `tool-errcode.html`（工具子页）
- `pages/feedback.html`（留言反馈，属工具线）

不覆盖：设备调试页（`device-*`）、E50 专属流程（已有自己的"技术&服务"入口）。

## 2. 需求摘要（已确认决策）

| 决策点 | 结论 |
|---|---|
| 展示范围 | 工具页及全部工具子页 |
| 打开形态 | 页面内全屏聊天层（不跳转页面，返回后保留当前工具页状态） |
| 演示深度 | 固定自动回复（与 E50 技术支持演示一致） |
| 实现方案 | 方案 A：共享小脚本 `assets/app/ai-assistant.js`，页面一行引入即生效 |

## 3. 组件架构

```
assets/app/ai-assistant.js   ← 新增，自包含（无外部依赖，不依赖 app.css/e50.js）
├─ 注入 <style>（悬浮球 + 聊天层专用样式，类名统一 .aa- 前缀，避免与 app.css 冲突）
├─ 构建 DOM（挂载到 body，定位在手机画布 .phone-shell/.phone-screen 内）
├─ 交互逻辑（打开/关闭、发送、固定自动回复、转人工）
└─ 暴露 window.GWDBG_AI_ASSISTANT（可选：open/close，供未来扩展）

各工具页面：一行 <script src="../assets/app/ai-assistant.js"></script> 引入
```

**为什么独立小脚本而不是复用 `interactions.js`：** `interactions.js` 是通用基础交互层（toast、对话框、chip 等），AI 助理是业务功能；保持独立脚本可在升级真实 AI 后端时只改一个文件，且不增加 `interactions.js` 的负担。

**样式注入原因：** 该脚本同时服务于 `_base.css` 工具线页面（当前）与未来可能的 `app.css` 页面；注入 `<style>` 保持脚本自包含，一行引入即生效，不需要页面再额外引样式。

## 4. 悬浮球设计

- **位置**：手机画布内右下，`right: 14px; bottom: calc(tabbar 高度 + 16px)`（工具 Tab 首页在 tabbar 上方；无 tabbar 的子页距底部安全区 16px）。
- **形态**：56×56 圆形，飞奕蓝渐变底，白色"AI"字样（或对话气泡图标），轻投影 + 呼吸微动画；点击有按压反馈。
- **层级**：`z-index` 低于聊天层，高于页面内容；工具 Tab 首页不被 tabbar 遮挡。
- **避让**：页面有底部固定操作按钮时（如"立即查询"），悬浮球自动上移避开（通过检测 `btn-block`/`query-btn` 等已知底部 CTA 的位置做最小避让，简化实现：统一放在屏幕右下但 `bottom` 预留 72px 以上空间，与查询按钮不重叠）。

## 5. 聊天层设计

**结构（复刻 E50 技术支持）：**

```
┌─────────────────────────────┐
│ ‹  AI 智能助理        ··· ○ │  ← 顶部栏（标题 + 关闭按钮）
├─────────────────────────────┤
│  今天 14:30                  │  ← 时间分隔
│  [客] 您好，我是飞奕技术支持  │  ← 欢迎语（agent 气泡 + 头像）
│  助手。请问有什么可以帮您？   │
│  [客] 如需人工专家支持，      │  ← action 卡片
│  可随时转接。 [转接人工客服]  │
│              用户消息气泡 [我]│  ← 用户发送后
│  [客] 已收到您的问题…(固定回复)│  ← 700ms 后固定自动回复
├─────────────────────────────┤
│ [转人工] [输入消息...] [发送] │  ← 底部输入栏
└─────────────────────────────┘
```

- **打开/关闭动画**：从右侧滑入（`transform: translateX(100%) → 0`，0.28s），关闭滑出；背景遮罩（`rgba(0,0,0,0.42)`）点击也可关闭。
- **定位范围**：`position: absolute; inset: 0` 于 `.phone-screen` 内（与 E50 侧栏一致，不超出手机画布）。
- **消息渲染**：纯 JS 字符串模板（与 `device-e50-service.html` 相同），esc 防注入；发送后 `scrollTop = scrollHeight` 滚到底。
- **固定自动回复**：发送任意消息 700ms 后追加："已收到您的问题，技术工程师会尽快回复。如需更及时的响应，可点击「转人工」。"
- **转人工**：输入栏"转人工"按钮与 action 卡片按钮均调用 `showToast('正在为您转接人工客服')`（复用 `interactions.js` 的 toast）。

## 6. 数据流

纯前端演示，无后端；消息存于脚本闭包的 `messages` 数组（每次打开页面重置，与 E50 演示一致）。会话不持久化。

```
点击悬浮球 → 构建/显示聊天层 → 渲染预置消息（时间+欢迎语+转人工卡片）
发送消息 → push user 消息 → 渲染 → 700ms → push agent 固定回复 → 渲染
点击转人工 → showToast
```

## 7. 错误与边界处理

| 场景 | 处理 |
|---|---|
| 输入为空 | 不发送，输入框无反应（与 E50 一致） |
| 重复快速点击悬浮球 | 聊天层已打开时忽略（幂等） |
| 输入含 HTML/脚本 | `esc()` 转义后渲染，防注入 |
| 页面已引入 `interactions.js` | 直接复用 `showToast`；未引入时脚本内置降级 toast |
| 同一页面重复引入脚本 | 检测 `window.GWDBG_AI_ASSISTANT` 已存在则跳过初始化 |

## 9. 不做的事（YAGNI）

- 不接真实 AI 后端、不做关键词问答、不做"正在输入"动效（原型演示用固定回复即可）；
- 不做消息持久化 / 历史记录；
- 不在设备调试页展示（E50 已有独立技术支持入口）；
- 不做拖拽移动悬浮球、不做多轮对话管理。
